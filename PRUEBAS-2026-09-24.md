  de código del mismo día.

**Cómo sigue:**
1. Probar con la checklist de abajo, sobre la rama
   (`git switch fix/auditoria-2026-09-23`).
2. Si algo falla, arreglarlo en la misma rama.
3. Cuando la checklist en dev y en el build de producción esté completa,
   pasar `scripts/check-redis.mts` y mergear a `main`. El merge es el
   deploy: producción toma los cambios recién ahí.
4. Después del merge, correr los pasos de "Después del deploy" y
   actualizar esta sección, la de `AUDITORIA-2026-09-23.md` y el addendum
   de `ARQUITECTURA.md` (sección 9) para decir que ya está en `main`.

**Preview de Vercel:** si el repo está conectado a Vercel, subir la rama
arma un deploy de preview con su propia URL. El cron diario corre solo en
producción, y el webhook de Mercado Pago apunta a `micaso.com.ar`, así que
el preview no los toca. Pero si las variables de Upstash del entorno
Preview son las mismas que las de Production, **abrir el preview lee y
escribe en la base real** con el código de la rama. Revisarlo en Vercel →
Settings → Environment Variables antes de usarlo para probar.

## Checklist manual

### Antes de empezar

- Dev: `npm run dev` → http://localhost:3000
- Entrar como corredora (Carolina): `/api/dev-login?role=broker`
- Entrar como super-admin: `/api/dev-login?role=superadmin`
- En dev **el service worker está apagado** (`next.config.ts`), así que
  offline y push se prueban con el build de producción (más abajo).
